# 2026-08-30 — CI/CD con PR-reviewer de IA (Idea 4 del roadmap grande)

Cuarta idea del roadmap de aprendizaje big-tech (ver [`proxmox-iac`](https://github.com/gaelsg/proxmox-iac) para las 3 anteriores). Elegido `devops-multiagent` como repo objetivo por tener más movimiento reciente y evals ya existentes que reutilizar como gate.

## Decisiones de diseño

**Runner self-hosted + Ollama local, no runners de GitHub + API de Claude.** Coherente con la filosofía "100% local y gratis" del proyecto — el review de PR usa el mismo `qwen3:14b` que ya corre en la RTX 5080 para el Diagnostician/Operator, cero costo de API. Trade-off: el runner tiene que estar prendido.

**El review de IA nunca bloquea el merge.** Mismo patrón de guardrail que Diagnostician/Operator: el modelo sugiere (comenta en la PR), un humano decide si mergea. Si Ollama falla o no responde, el job termina en éxito sin comentar — no hay forma de que un LLM caído tumbe el pipeline.

**Guardrail de seguridad: `if: head.repo.full_name == github.repository` en ambos jobs.** Un runner self-hosted en un repo público es RCE-as-a-service si se le permite correr workflows disparados por PRs de forks — es un vector de ataque real y documentado en la industria (ver incidentes conocidos de supply-chain vía self-hosted runners). Como hoy este repo es de un solo mantenedor, el riesgo actual es bajo, pero la mitigación se aplicó desde el día uno en vez de esperar a necesitarla.

## Incidente durante el registro del runner

El primer intento de registrar el runner falló dos veces por errores de shell, no de la infraestructura en sí:
1. Un bloque de comandos con continuaciones `\` se pegó mal en la terminal (fish, bracketed paste), causando que `curl` se comiera la siguiente línea como argumento.
2. La sintaxis `VAR=$(comando)` es de bash, no de fish — fish requiere `set VAR (comando)`.

Ninguno de los dos dejó estado parcial (el directorio del runner quedó vacío ambas veces). Se corrigió reescribiendo el bloque sin continuaciones de línea y con sintaxis fish nativa.

**Identidad de git perdida:** al momento de commitear, `git config --global user.name/user.email` estaban vacíos (se habían perdido en algún punto entre la Idea 3 y esta). Se le pidió al usuario que los reconfigurara él mismo (el asistente no toca `git config` global por su cuenta).

## Verificado

- Runner registrado, scoped solo a este repo (no a la cuenta/org), instalado como servicio systemd (`sudo ./svc.sh install/start`) — sobrevive reboot.
- Pipeline probado con una PR real (`test/ci-pipeline`): job `test` corre `gate_unit_tests.py`, job `ai-review` genera un comentario con `qwen3:14b` sobre el diff real. Ver el PR para el resultado exacto.
