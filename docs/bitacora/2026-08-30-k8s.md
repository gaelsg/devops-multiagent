# 2026-08-30 — Diagnostician conectado a Kubernetes (Idea 6 del roadmap grande)

Parte de la Idea 6, última del roadmap grande (ver [`k8s-mcp-server`](https://github.com/gaelsg/k8s-mcp-server) para el detalle completo del cluster y el servidor MCP). Esta entrada es solo el lado de este repo.

## Cambio
`diagnostician.py` conecta un tercer servidor MCP (`k8s`), sin gate — `k8s-mcp-server` no tiene ninguna tool de escritura, así que no hay nada que bloquear en código (mismo criterio que `docker_tools.py` en `proxmox-mcp-server`).

## Colisión de nombres evitada
`proxmox-mcp-server` ya expone una tool `list_nodes` (nodos físicos de Proxmox). `k8s-mcp-server` iba a exponer otra `list_nodes` (nodos del cluster de Kubernetes) — `ToolRegistry.connect()` no namespacea tools por servidor, así que el segundo hubiera pisado al primero silenciosamente. Se renombraron las tools de `k8s-mcp-server` con prefijo `k8s_` (`list_k8s_nodes`, etc.) antes de conectarlo, no después de encontrar el bug.

## Verificado
`uv run devops-agent diagnose "cuantos pods estan corriendo en el cluster de kubernetes y en que namespace"` → respuesta correcta, tool call real: `list_k8s_pods({'namespace': None}) -> ejecutado`. `evals/gate_unit_tests.py` sigue en verde (5/5) tras el cambio.
